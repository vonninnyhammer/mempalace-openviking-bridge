# MemPalace ↔ OpenViking Bridge

A dual-layer, local-first memory architecture: **spatial** memory (MemPalace,
ChromaDB + SQLite) and an **execution-time RAG** filesystem (OpenViking,
`viking://`). Every layer runs on local hardware — **zero cloud telemetry.** The
bridge tiers the two so the cheap store answers "where is it" and the semantic
store answers "what does it mean."

```
┌────────────────────────────┐        ┌──────────────────────────────┐
│  LAYER 1: MemPalace       │        │  LAYER 2: OpenViking         │
│  (pip, MIT)               │        │  (Docker, stock image)       │
│                           │ bridge │                              │
│  Ingestion & spatial      │───────▶│  Execution-time RAG context  │
│  structuring:             │        │  filesystem (viking://)      │
│  Wings / Rooms / Halls /  │        │  L0 abstract / L1 overview / │
│  Drawers                  │        │  L2 detail                   │
│  ChromaDB + SQLite (local)│        │  local port, key auth        │
└────────────────────────────┘        └──────────────────────────────┘
        │                                        │
        └── escalation_listener.py ──▶ local agents / n8n
```

## Why two stores instead of one

- **MemPalace** is great at spatial organization (a document "lives in room X
  of wing Y") and it survives on very little RAM.
- **OpenViking** adds a semantic filesystem where every folder gets an
  *L0 abstract*, an *L1 overview*, and full *L2 detail* generated by an
  embedding model + a vision-language model — i.e. context an agent can
  retrieve at the right granularity at execution time.

The bridge keeps them in sync idempotently and routes **low-confidence or
unresolved queries** into a structured escalation queue instead of silently
returning junk.

## Bridge pipeline (`bridge/mempalace_viking_bridge.py`)

1. **Export** — read drawers from the MemPalace ChromaDB collection, highest
   `importance` first. OpenViking spends about 12 s per resource generating its
   abstracts on a CPU VLM, so the whole palace is not pushed: `--min-importance`
   (default 2.0) and `--max-drawers` (default 60, 0 = no cap) keep viking:// a
   small, high-signal set while the palace stays the full-corpus search layer.
2. **Stage** — write drawers into a staging tree laid out as
   `viking://resources/mempalace/{wing}/{room}/...`. The manifest records each
   drawer's path and SHA-1, so a drawer whose text changes is restaged, and
   staged files that fall out of the set are deleted so the cap holds.
3. **Sync** — `add_resource(...)` to OpenViking; OpenViking generates L0/L1/L2
   via its configured embedding + VLM.
4. **Verify** — poll the raw HTTP API for non-empty directory abstracts
   (OpenViking's SDK strips the `abstract` field; the raw API does not).

Idempotent: unchanged drawers are skipped; `--full` rebuilds staging.

## Capture cycle (`bridge/capture.sh`)

Runs on a timer: OpenCode sessions -> MemPalace -> importance ranking.

- `bridge/opencode_exporter.py` reads `opencode.db` read-only and writes one
  transcript per session in MemPalace's `> user / assistant` format. It is
  incremental (a session is rewritten only when its text changes); tool outputs
  are left out, tool names and the files each session edited are kept.
- `mempalace mine --mode convos` files them. If the local embedder is down or
  another process holds the palace lock, mining is retried and then deferred to
  the next cycle instead of failing.
- `bridge/rank_drawers.py` writes the `importance` field that MemPalace's L1
  sorts on but nothing else sets: user turns and decisions score higher than
  tool markers, and scores decay with the age of the conversation. Set
  `MEMPALACE_PROPER_NOUNS` to the names of your own projects to boost them.

Paths default to this checkout; override with `MEMPALACE_VENV`,
`MEMPALACE_INGEST` and `MEMPALACE_CAPTURE_LOG`.

## Escalation (`bridge/escalation_listener.py`)

Triggers, all evaluated locally:

| Trigger         | Condition                                        |
|-----------------|--------------------------------------------------|
| `low_confidence`| top hit similarity < 0.55                        |
| `unresolved`    | zero recall for a query                          |
| `anomaly`       | drawer count below floor (palace looks empty)    |

Each trigger becomes a structured payload (`mempalace.escalation.v1`) that is
(a) written to a durable local queue as JSON, (b) handed to a local agent via
the Hermes CLI, and (c) optionally POSTed to a local n8n webhook. Nothing leaves
the machine.

## Integration test (`bridge/integration_test.py`)

End-to-end validation: generate a sample log → ingest through MemPalace →
run the bridge → retrieve via `viking://` → assert **all model endpoints are
local** (checks `ov.conf` API bases fall in private ranges only). Exit code 0
means everything passed.

## Example config

```yaml
# mempalace.yaml — what the in-source `mine` command files into which wing
wing: mempalace_viking
rooms:
- name: bridge
  description: Files from bridge/
- name: escalations
  description: Files from escalations/
- name: ingest
  description: Files from ingest/
- name: test_data
  description: Files from test-data/
- name: logs
  description: Files from logs/
```

OpenViking is pointed at a **local Ollama** for both embeddings
(`nomic-embed-text`, 768-dim) and its VLM, all on CPU. See `Deployment`
details in the code docstring; the `ov.conf` it expects looks like:

```json
{
  "storage":  { "workspace": "/app/.openviking/data", "vectordb": {"name": "context", "backend": "local"}, "agfs": {"backend": "local"} },
  "embedding": { "dense": { "provider": "ollama", "api_base": "http://<local-ollama>:11434/v1", "api_key": "ollama", "model": "nomic-embed-text", "dimension": 768 } },
  "vlm": { "provider": "openai", "api_base": "http://<local-ollama>:11434/v1", "api_key": "ollama", "model": "llama3.2:3b", "timeout": 120 },
  "server": { "host": "0.0.0.0", "port": 1933, "auth_mode": "api_key", "root_api_key": "<generated at first run>" }
}
```

## Field notes (real things that bit me)

- **OpenViking `ls` hides dotfiles** — `.abstract.md` / `.overview.md` sidecars
  don't appear, but each directory exposes its generated L0 as an `abstract`
  field. Poll that instead.
- **The SDK strips `abstract`** on `ls` — use the raw HTTP API for health checks.
- **`qwen3` models ignore `think:false`** in Ollama and burn budget on
  chain-of-thought; use non-reasoning models (e.g. `llama3.2:3b`) for the VLM.
- **Docker pulls intermittently fail over IPv6** — retries resume over IPv4.
- **MemPalace `mine` skips `.log` extensions** — use `.txt`/`.md` for log content.

## Constraints

- All stores, models, and routing are local / on the private mesh. No cloud.
- CPU-only inference; quantized models sized to fit RAM.
- No public ports — OpenViking is reachable only inside the WireGuard mesh.

Hobby/research scaffold — a deliberately over-built memory layer that works like
a chain-of-thought scratchpad for agents.
